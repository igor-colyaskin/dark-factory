Governance and Lifecycle

All cards have a life cycle for one year. After one year all card owners will be informed about end of life and if card needs to be extended.

If a card has no valid owner or responsible person anymore the card will be deactivated/deleted.

If a card breaches against any SAP policies the card will be deactivated/deleted.

SWZ admins will drop a public note in case we need to deactivate a card.

Enduser documentation is located in SAP Work Zone Help Center.

Technical documentation is located in TBD (extra App, Wiki, protected Excel sheet).

Development and Deployment

Cards will be developed first in SWZ Dev. Cards need to be tested and approved by QA and PO in SWZ QA. Cards will be deployed once all above requirements are fulfilled and tested properly.

Any card must have secure libraries. Only SAP internal libraries are allowed. Connections to any outside SAP network (libraries, services) are not allowed.

Code needs to be checked via CheckMarx and GitHub Scanner for security vulnerabilities. Code needs to be scanned by Dependency Scanner: Whitesource, Blackduck.

  • Connections via BTP Destinations only
  • API calls from SWZ or Source System are ok
  • New OAuth clients need to be requested via ticket and final approval by PO
  • All authorization goes through Workzone
  • Languages allowed: JavaScript
  • Source code must be located in SAP GitHub
