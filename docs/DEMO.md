# DF-IC Demo — заметки для питча

Аудитория: тимлид. Формат: показываю сам, в конце — "хочешь попробовать?".

---

## Ключевые тезисы

### DF-IC + Vibe coding = полный workflow

DF-IC покрывает воспроизводимые 80%: структура карточки, маппинг полей,
mock-данные, тесты, sandbox preview — за ~1 минуту вместо ~2 часов вручную.

Для оставшихся 20% — специфика команды, нестандартные паттерны,
индивидуальные требования — вайб-кодинг на готовом скаффолде работает
быстрее и надёжнее, чем пытаться описать всё это в промпте.
Это не ограничение — это дизайн-принцип: правильное разделение труда
между генерацией и кастомизацией.

## Задел на draft-v3 (материал, содержание ещё зреет)

### Горизонт — уточнённый фрейм

Абстрактное «паттерн универсальный» заменить на конкретную боль команды:

> *«Следующая дыра — документация. Сейчас это ручная работа без правил:
> каждый пишет что-то своё, или не пишет вообще. Паттерн тот же —
> воспроизводимая работа, которую легко стандартизировать.»*

**Почему это сильнее:** тимлид не чувствует эту боль лично, но отвечает
за команду. Аргумент — не «тебе неудобно», а «твоя команда тратит время
на работу без критериев». Это его зона ответственности.

### Сервис changelog / документации (будущий тайл)

Идея: просмотреть последние коммиты карточки → LLM резюмирует изменения →
обновляет README (версия N, что изменилось) + генерирует фрагмент для Confluence
рядом с карточкой (copy-paste вручную, 30 сек).

Реализация: самодостаточная, без внешних API. После демо — чистая задача в бэклог.

### Анекдот для mini-intro Block 2

История с тимлидом, который вручную проставлял version bump после своих правок —
использовать как вербальный пример человеческого фактора. Не демо-сценарий
(функции нет), просто живая иллюстрация тезиса.
