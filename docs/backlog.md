## Визуализация

### [VIZ-001] Local sandbox для предпросмотра сгенерированной карточки
**Источник:** устное обсуждение, сессия 2026-05-08  
**Приоритет:** топ-3 (если технически реализуемо — подтверждено, что да)  
**Суть:** После успешного DEV_CHECK показывать живую карточку с mock-данными прямо в DF UI.  
**Архитектурная гипотеза:** центральный sandbox-сервер внутри DF (один экземпляр) с копией SDK,
умеет загружать любой сгенерированный workspace по cardSlug. SDK не копируется в каждый workspace.  
**SDK:** лежит в GitHub, копируется — утилита/пакет для копирования есть. Нужны ~4-5 файлов
(Base.controller, ErrorHandler, AuthorizationDialog.controller, CustomError). Не весь пакет.  
**Sandbox в проекте:** в команде есть изолированный sandbox на уровне карточки (эмуляция WZ без реальных destinations)
— именно он нужен. Есть ещё общий sandbox с destination на dev-среду — не наш случай.  
**Нужна сессия:** что, когда, как — последовательность, приоритеты, блокеры. Ещё не проектировали.  
**Возможные блокеры:** лицензия на копирование SDK, CORS при iframe-рендеринге, lifecycle сервера.

## UX

### [UX-001] Кнопка "Уточнить" на экране Spec Review
**Источник:** устное обсуждение, сессия 2026-05-08  
**Суть:** Сейчас в SPEC_REVIEW только Cancel и Submit. Cancel = начать сначала.  
Нужна кнопка "Уточнить" (или "Изменить") — переводит обратно в CLARIFYING с сохранённым spec.  
Пользователь вводит уточнение ("добавить поле phone"), Архитектор обновляет spec, снова SPEC_REVIEW.  
**Трейдофф:** нужен новый переход состояния SPEC_REVIEW → CLARIFYING + Архитектор должен получить текущий spec как контекст.
