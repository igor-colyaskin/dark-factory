# UX-001 — Кнопка «Уточнить» на экране Spec Review

**Статус:** в проектировании  
**Приоритет:** первая фаза после v0.9

---

## Проблема

На экране SPEC_REVIEW только две кнопки: **Cancel** и **Start**.
Cancel вызывает `orchestrator.reset()` → IDLE — вся история уточнений теряется.
Если пользователь хочет исправить поле или добавить требование, ему нужно начинать с нуля.

---

## Цель

Новый переход: `SPEC_REVIEW → ARCH_WORKING → ... → SPEC_REVIEW`  
Пользователь вводит уточнение → архитектор пересматривает spec → снова SPEC_REVIEW с обновлённым результатом.

---

## Что выяснено по коду

| Что | Где |
|-----|-----|
| `currentSpec` хранится в `orchestrator.currentSpec` и есть в `getState()` | `server/orchestrator.js:122, 197` |
| `clarifyHistory` и `clarifyRound` сохраняются всё время | `server/orchestrator.js:117-121` |

| IC-профиль имеет свой `generateUserPrompt` | `server/prompts/integration-card/architect.js` |

## Подход (согласовать)

### Механизм

1. Пользователь нажимает **«Уточнить»** → появляется textarea
2. Вводит уточнение («добавить поле phone», «изменить destination на HR_API»)
3. Сообщение добавляется в `clarifyHistory` как специальный раунд
4. `clarifyRound` сбрасывается (даём архитектору свежие раунды)
5. `currentSpec` передаётся архитектору как контекст («вот что ты сгенерировал, пользователь хочет изменить»)
6. Переход → `ARCH_WORKING` → архитектор либо задаёт вопросы → `CLARIFYING`, либо сразу → `SPEC_REVIEW`

### Новый метод оркестратора

```js
async handleRefineRequest(message) {
  if (this.state !== STATES.SPEC_REVIEW) throw new Error(...)
  
  // Добавляем refinement как новый раунд в историю
  this.clarifyHistory.push({ refine: true, message });
  this.clarifyRound = 0;  // свежие раунды для архитектора
  // currentSpec НЕ очищаем — передадим архитектору как контекст
  
  await this.transition(STATES.ARCH_WORKING, ...)
}
```

### Изменение в архитекторе

`generateUserPrompt` получает новый параметр `previousSpec`.  
Если задан → архитектор видит: «Вот spec который ты уже сделал. Пользователь просит изменить: [message]. Обнови spec.»

Это правило добавляется в обоих архитекторах: `architect.js` (generic) и `integration-card/architect.js`.

## Решения

1. **Архитектор при уточнении** — обычный flow (может задать вопрос или сразу spec)
2. **Экран во время пересмотра** — spec скрывается, показывается стандартный ARCH_WORKING спиннер. Оценить на догфудинге.
3. **Лимит refinement-раундов** — **3** (симметрично с `maxClarifyRounds`). Если за 3 раунда spec не тот — проблема в исходном заказе, проще начать сначала.
