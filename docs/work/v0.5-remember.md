# v0.5 — REMEMBER (Order by Reference)

**Статус:** завершено
**Начато:** 2026-05-06
**Завершено:** 2026-05-06

---

## Цель

Архитектор умеет использовать прошлый заказ как baseline.
Пользователь нажимает "Повторить с изменениями" на карточке — и описывает только дельту.

**Ключевое обучение:** насколько хорошо архитектор работает в режиме
"возьми готовое и измени", а не "сделай с нуля".

---

## Scope

### В v0.5
- `readApp` в `github-client.js` — читает SPEC.md из репо по `sourceUrl`
- Кнопка "Повторить с изменениями" в Products → открывает Order tab
  с префиксом `На основе #N:` в textarea
- Оркестратор: детектирует префикс, читает spec через `readApp`,
  передаёт архитектору как `referenceSpec` (целиком)
- Architect prompt: новый режим входа с `referenceSpec` + дельта от пользователя
- Dogfooding: 2 заказа "на основе прошлого"

### Явно вне scope
- Текстовый парсинг "как #25" без UI-кнопки
- Pattern Library → Area-51
- Обновление существующего репо (update вместо create new)
- Feedback loop → v0.6

---

## Принятые решения

| Решение | Причина |
|---------|---------|
| Передавать весь spec целиком | Spec маленький, overhead минимален; вопрос не в объёме, а в поведении архитектора |
| UI-кнопка, не текстовый парсинг | Детерминированный триггер, принцип Guided decisions |
| Создаём новое репо, не обновляем старое | Проще, update — v0.6 territory |

## Фазы

### Фаза 1: `readApp` — чтение spec из GitHub
- Реализовать `readApp(sourceUrl)` в `server/github-client.js`
- Читает `SPEC.md` из репо, возвращает строку
- Обработка: `sourceUrl: null` → возвращает `null` (graceful fallback)
- Тест: скрипт `scripts/test-read-app.js`

### Фаза 2: Оркестратор — reference detection
- Детектировать префикс `На основе #N:` в `orderDescription`
- Резолвить `#N` → `sourceUrl` через `appsStore`
- Вызвать `readApp`, положить результат в `state.referenceSpec`
- Если `readApp` вернул `null` (GitHub недоступен или `sourceUrl` нет) —
  продолжить как обычный заказ, без блокировки

### Фаза 3: Architect prompt — режим reference
- Обновить `server/prompts/architect.js`
- Если `referenceSpec` передан — включить в user prompt как baseline
- Инструкция: "используй как основу, применяй только описанные изменения"
- Калибровочный тест: 3-5 reference-заказов через `mock:fast`

### Фаза 4: UI — кнопка "Повторить с изменениями"
- На карточке Products: новая кнопка рядом с "Стереть"
- Действие: переключить на таб Order, вставить `На основе #N: ` в textarea,
  сфокусировать курсор после префикса
- Если `sourceUrl: null` у приложения — кнопка disabled с tooltip

### Фаза 5: Интеграционный тест
- `npm run mock:fast` — прогнать reference-заказ end-to-end
- Live-прогон: 1 reference-заказ с реальным LLM
- Проверить: новое репо создано, spec отражает изменения, старый spec не потерян

### Фаза 6: Dogfooding + документация
- 2 реальных заказа "на основе прошлого", записать инсайты
- Обновить `docs/contracts.md` — Source Storage, Orchestrator state
- Обновить `CONCEPT.md` версия → v0.5
- Обновить `docs/log.md` — решения, инсайты, фазы
- Тег `v0.5`, запись в `ROADMAP.md`
