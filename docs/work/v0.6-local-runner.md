# v0.6 — Local Runner

**Статус:** в работе
**Начато:** 2026-05-06
**Завершено:** —

---

## Цель

Заменить Fly.io на локальный запуск сгенерированных приложений.
Полный pipeline (включая GITHUB_PUSH) работает на корп. VDI без внешних зависимостей.

**Ключевое обучение:** проектирование Deployer-контракта по принципу
"интерфейс выводится из реальной потребности, не из спекуляции".

---

## Scope

### В v0.6
- `server/local-runner.js` — запускает приложение локально, возвращает `http://localhost:PORT`
- `workspaces/{appName}/` — изолированный workspace для каждого приложения
- In-memory process registry — teardown при удалении приложения
- Оркестратор: `executeLocalDeploy()` вместо `executeDeploy()` в реальном режиме
- UI Products: кнопка "Открыть" (on-demand запуск) вместо постоянного URL; QR убран
- Догфудинг: 2 полных заказа end-to-end

### Явно вне scope
- Deployer facade/абстракция — до появления второй имплементации
- Кеш-стратегия и eviction для `workspaces/` → Area-51
- Fly.io адаптер → Area-51 (VDI заблокирован)
- Авто-рестарт приложений при старте сервера

---

## Принятые решения

| Решение | Причина |
|---------|---------|
| Workspace per app: `workspaces/{appName}/` | Изоляция; диск растёт, но критерии eviction неизвестны — решим по факту |
| On-demand UX: кнопка "Открыть", не постоянный URL | Честная модель для локального раннера; снимает проблему persistence после рестарта |
| No Deployer facade | Контракт выводится из двух реализаций, не из одной |
| puppeteer-core + системный Chrome | Проверено на VDI — работает |

## Фазы

### Фаза 1: `local-runner.js`
- Найти свободный порт (диапазон 3100–3999)
- Скопировать `workspace/` → `workspaces/{appName}/`
- Запустить `npm install` (если нет `node_modules`), затем `npm start`
- Дождаться HTTP 200 на `http://localhost:PORT` (polling, таймаут 60 сек)
- Вернуть `{ url, pid, port }`
- `teardown(appName)` — убить процесс, опционально удалить папку
- Тест: скрипт `scripts/test-local-runner.js`

### Фаза 2: Process registry
- In-memory Map `{ appName → { pid, port, startedAt } }` в `server/process-registry.js`
- `register(appName, { pid, port })`, `get(appName)`, `remove(appName)`, `list()`
- При удалении приложения: `registry.get(appName)` → `teardown` → `registry.remove`

### Фаза 3: Оркестратор
- `executeLocalDeploy()` — вызывает `localRunner.deploy()`, получает URL, пишет в `this.publicUrl`
- В `startOrder()`: реальный режим → `executeLocalDeploy()` вместо `executeDeploy()`
- Mock-режимы (`mock:fast`, `demo`) не трогаем — `executeFakeDeploy()` остаётся
- Удалить retry-логику специфичную для Fly (deploy timeout 300 сек → 90 сек для локального)

### Фаза 4: Delete flow
- В `DELETE /api/apps/:id`: перед удалением из store — `registry.get(id)` → teardown если запущен
- `deleteApp` в `github-client.js` — без изменений

### Фаза 5: UI
- Products: убрать QR-код для `localhost` URL
- Products: кнопка "Открыть" — POST `/api/apps/:id/open` → запускает если не запущен → redirect
- Индикатор состояния на карточке: "Запущено" / "Остановлено"
- `GET /api/apps/:id/status` — проверяет process registry, возвращает `{ running, url }`
- **Примечание v0.7:** в таблице агентов на странице Order предусмотреть строку для Verifier
  (сейчас: Architect / Developer / Tester — нужно место для четвёртого)

### Фаза 6: Интеграционный тест

- Live-прогон: 1 полный заказ с LLM включая GITHUB_PUSH
