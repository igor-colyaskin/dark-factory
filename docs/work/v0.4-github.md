# v0.4 — GitHub Integration

**Цель версии:** код сгенерированных приложений сохраняется в GitHub
как отдельный репозиторий в аккаунте пользователя. Открывается
путь к REMEMBER (v0.5), где Architect будет работать с существующим
кодом, а не регенерировать его.

**Контекст модульной архитектуры:**
GitHub Client — первая имплементация **Source Storage** контракта.
Оркестратор обращается к нему через состояние `GITHUB_PUSH`, но контракт
проектируется с учётом будущих бэкендов. Поле `sourceUrl` (не `githubUrl`)
обеспечивает абстракцию от конкретной реализации.

**Pipeline после v0.4:**
`Order → Negotiate → Spec → Start → Dev → Test → Deploy → GITHUB_PUSH → Done`

## Дизайн-решения

### Source Storage контракт

GitHub Client реализует контракт Source Storage:
- `saveApp(appName, files, meta) → sourceUrl` — создать репо, закоммитить файлы
- `deleteApp(appId) → void` — удалить репо
- `readApp(appId)`, `updateApp(appId, files)` — зарезервировано для v0.5 REMEMBER

Facade-модуль `storage.js` НЕ создаётся до появления второго бэкенда.
Принцип: "контракт выводится из двух реализаций, не из одной".

### Model

- **OAuth App** для авторизации (не PAT)
- **Один репозиторий на приложение**
- **Имя:** `df-<slug>-<number>` (e.g. `df-todo-app-509`) — унифицированное
  для Deployer и GitHub. Упрощает навигацию между компонентами.
- **Privacy:** приватные по умолчанию (настраивается в Settings)
- **Owner:** аккаунт пользователя (не DF)

### Содержимое репозитория

```
<repo-name>/
  README.md       ← автогенерация: описание, запуск, бэдж DF
  SPEC.md         ← копия spec от Architect
  app.js          ← код от Developer
  package.json
  public/         ← если есть frontend
  .gitignore      ← стандартный Node.js
```

### Timing

Коммит происходит **после успешного деплоя**. Если деплой упал —
репозиторий не создаётся. Концепция: репозиторий содержит только
работающий код.

### GITHUB_PUSH — non-blocking

Если GitHub недоступен или пользователь не подключил аккаунт —
заказ всё равно завершается (DONE). GitHub-push — бонус, не блокер.
В `sourceUrl` записывается `null`, в UI показывается notice.

### Deploy flow

Деплой через **Deployer** (текущая имплементация: Fly.io или Local Runner).
GitHub — архив и история, не источник деплоя.

### GitHub Topics (автоматически)

- `dark-factory`
- `ai-generated`
- `nodejs`
- тематические из spec (опционально)

## Решённые вопросы

| # | Вопрос | Решение |
|---|--------|---------|
| 1 | OAuth App: в чьём аккаунте? | Личный GitHub-аккаунт. Перенос в org — опционально |
| 2 | Scope токена | `repo` (полный доступ, нужен для приватных) |
| 3 | Хранение токена | `state/github-tokens.json`, плоский файл, в gitignore |
| 4 | Без подключения GitHub? | Заказ выполняется, `sourceUrl: null`, notice в UI |
| 5 | SPEC.md формат | JSON + readable markdown (финализация в Phase 4) |
| 6 | Products UI | Иконка GitHub на карточке + секция Source Code в Details |
| 7 | App name = repo name | Да: `df-<slug>-<number>` для обоих |
| 8 | Метрики в apps.json | Поле `sourceUrl` (не `githubUrl`) |
| 9 | Коллизия имён | Суффикс `-2`, `-3` при конфликте |

## План реализации

### Phase 0: Design ✅

Дизайн-решения зафиксированы выше.

### Phase 1: OAuth App Setup ✅

GitHub OAuth App зарегистрирована, callback работает,
токен получается и сохраняется.

**Коммит:** `v0.4 phase 1: github oauth setup`

### Phase 2: GitHub Client Module ✅

Модуль `server/github-client.js`: `getUser`, `createRepo`, `setTopics`,

validation, server_error. Тест: `scripts/test-github-client.js`.

**Коммит:** `v0.4 phase 2: github client module`

### Phase 3: Orchestrator Integration ✅

**Цель:** после успешного деплоя оркестратор вызывает GitHub Client.
Non-blocking: если GitHub упал — заказ завершается.

- [ ] 3.1 Новое состояние `GITHUB_PUSH` между deploy и DONE
- [ ] 3.2 Проверка: GitHub подключен? (`githubTokens.isConnected()`)
  - Не подключен → skip, log notice, proceed to DONE
  - Подключен → create repo, commit files, get sourceUrl
- [ ] 3.3 Rollback: если репо создан, но коммит упал → удалить репо
- [ ] 3.4 Сохранение `sourceUrl` в archiveApp()
- [ ] 3.5 SSE broadcast: "Pushing to GitHub..."
- [ ] 3.6 Определение файлов для коммита: чтение workspace/

### Phase 4: README.md + SPEC.md

## Риски

| Риск | Митигация |
|------|-----------|
| OAuth callback сложнее ожидания | Phase 1 отдельная. Fallback: PAT временно |
| GitHub API rate limits (5000/час) | Далеко от лимита при 1 пользователе. Retry с backoff |
| Токен истёк / отозван | Детектировать 401, снова authorize |
| Репо создался, коммит упал | Rollback: удалить репо |
| README выглядит плохо | Визуальный тест на 5-6 приложениях |
